# Phase 2 — Authentication, RBAC & Access Control

## Approved Decisions

### 1. Super Admin — Platform-level, NOT in shop_user
- `users` table gets `is_super_admin TINYINT(1) DEFAULT 0` column
- `shop_user` roles remain: owner, admin, operator, customer only
- Super admin does not require shop_id
- Can access all shops and users

### 2. OTP SMS — Abstract interface created now
- `core/OtpManager.php` — orchestrates OTP lifecycle
- `services/SmsProviderInterface.php` — interface for SMS providers
- `Mailer` used for email OTP; SMS left as pluggable

### 3. Remember Me — Persistent cookie token
- Store hashed token in login_tokens table
- 30-day expiry, HttpOnly + Secure + SameSite
- On auto-login: validate, regenerate session, rotate token
- Invalidate on logout

## Overview
Build a complete production-ready authentication and authorization system on top of the existing Phase 1 foundation.

### Key Design Decisions

1. **Rate Limiting** — `RateLimiter` uses MySQL `failed_logins` table (consistent with MySQL-first approach). Configurable: 5 attempts, 15-min lockout (from `settings` table defaults).

2. **Super Admin** — New `super_admin` role in `shop_user.role` ENUM. Super admins are platform-level, not scoped to a shop. They see an admin sidebar with platform management links. The `Middleware::superAdmin()` checks `AuthContext::isSuperAdmin()`.

3. **Login Flexibility** — The login form uses Alpine.js tabs for email/phone/username. The controller detects the input type and queries the appropriate field.

4. **OTP System** — `OtpManager` generates 6-digit codes, stores in `login_tokens` table with 5-min expiry. Sends via `Mailer` (abstract — SMS provider can be plugged in later). Tracks attempts in `otp_attempts` table (max 3 attempts, then 15-min lock).

5. **Remember Me** — Persistent cookie with a random token stored in `login_tokens` table (30-day expiry). On login with "remember me" checked, a cookie is set. On session expiry, the cookie is checked and user is auto-logged-in.

6. **Permission Middleware** — `requirePermission('users.create')` pattern already exists in `Middleware::permission()`. Enhanced with `requireRole('super_admin')` and `requireAnyPermission([...])`.

### Testing Plan

| Test | What to verify |
|------|---------------|
| Login success | Email/phone/username login with correct password redirects to dashboard |
| Wrong password | Returns error flash, increments failed login counter |
| Locked account | After 5 failed attempts, account locked for 15 min |
| CSRF failure | POST without valid CSRF token returns 419 or redirects |
| Permission denied | User without permission gets 403/redirect |
| Shop isolation | User in Shop A cannot access Shop B data |
| Role-based dashboard | Owner sees all, operator sees limited, customer sees own |
| OTP verify | Valid OTP logs in, invalid OTP shows error, max 3 attempts locks |
| Forgot password | Email sends reset link, token expires after use |
| Super admin | Can view all users, activate/deactivate, change roles |
| Staff invite | Shop owner can invite, assign role, remove staff |
| Profile page | User can view/edit profile, change password, manage sessions |
