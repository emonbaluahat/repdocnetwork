# STARTUP PLAN — RepDoc Network

## VISION
RepDoc Network is an operating system for Computer Shops, Digital Service Centers, Document Professionals, and Remote Operators in Bangladesh. It combines document generation, CRM, shop management, marketplace, wallet, community, and hiring into one ecosystem.

---

## PHASE OVERVIEW (5 Phases, ~18 Months to V1 Market Fit)

| Phase | Name | Duration | Outcome |
|-------|------|----------|---------|
| 0 | Foundation (Existing) | Done | prottoyon.gov.bd clone + admin panel + Bangla cert generation |
| 1 | Core SaaS (DocOS Base) | Months 1-4 | Multi-tenant shop platform with CRM + Document Engine v2 |
| 2 | Marketplace & Community | Months 5-8 | Service marketplace, shop-to-shop, remote operators, community |
| 3 | Wallet & Monetization | Months 9-12 | Wallet, escrow, template/plugin marketplaces, analytics |
| 4 | Advanced Features | Months 13-16 | Hiring portal, AI, mobile app, desktop app, multi-language |
| 5 | Scale & Ecosystem | Months 17-24+ | Elastic scale, API marketplace, global expansion, enterprise |

---

## TECH STACK

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| Backend | PHP 8.3 (Custom MVC) | Full control, no framework overhead, easy to hire in BD |
| Frontend | HTML + CSS + JavaScript (Vanilla JS with Composable architecture) | Lightweight, no build step, PHP templates render server-side |
| Template Engine | PHP (plain includes/requires or custom lightweight) | Avoids Blade/Twig dependency, keeps it simple |
| Database | MySQL 8 | Reliable, widely supported, excellent for structured data |
| PDF | Dompdf / mPDF | PHP-native, supports Bangla/Unicode via font embedding |
| Queue | MySQL-based job table + cron | Simple, no extra services needed initially |
| Search | MySQL FULLTEXT indexes | Good enough for Phase 1-2, no extra infrastructure |
| Cache | File-based or MySQL query cache | Minimal dependencies for V1 |
| File Storage | Local filesystem + MySQL metadata | Upgrade to cloud backup in Phase 3 |
| Real-time Chat | AJAX polling (short-interval) | Works without WebSockets, upgrade later |
| CSS Framework | Tailwind CSS (via CDN or compile-once) | Stripe/Linear aesthetic without JS framework |
| JS Utilities | Alpine.js or vanilla JS modules | Lightweight interactivity without React |
| Auth | PHP session-based + password_hash (bcrypt) | Simple, proven, secure |
| Deployment | LAMP stack (Linux + Apache/Nginx + MySQL + PHP) | Standard BD hosting, no Docker needed |
| Monitoring | Custom error logging + Uptime monitoring | Start simple

### Month 2: Customer CRM & Document Engine

#### Task 2.1: Customer CRM


#### Task 2.2: Document Engine v2
The most critical module. Must handle Bangla + English text with perfect formatting.

- **Template System** (Admin/Super-admin creates templates)
  - Templates stored as HTML/PHP fragments with placeholder variables
  - Variables system: `{customer_name}`, `{date}`, `{certificate_no}`
  - Conditional blocks: `{if gender==male} his {else} her {/if}`
  - Dynamic tables, signatures, QR codes, photos

- **Document Generation**
  - Accept template ID + field values
  - Render template HTML with substituted variables
  - Convert HTML to PDF using Dompdf or mPDF (PHP-native, good Bangla support)
  - Generate DOCX simultaneously using PHPWord for editable versions
  - Optional: Email PDF to customer directly (PHP mailer or PHPMailer)
  - Heavy generation queued via MySQL jobs table + cron (user gets notification when ready)

- **Document Types** (initial)
  - Character Certificate
  - Birth Certificate
  - Income Certificate
  - Student Certificate
  - Land Ownership Certificate (khotian)
  - Trade License
  - NID Copy
  - Custom/blank certificates
  - Each type has its own field set and template

- **Document Management**
  - List all generated documents (shop-wide)
  - Filter by date, type, customer, operator
  - Re-download anytime
  - Cancel/void a document
  - Regenerate with corrections
  - Document references (unique alphanumeric codes for tracking)

#### Database Tables: Documents
```sql
document_templates (id, shop_id|nullable, name, slug, type, content_structure, variables, thumbnail, is_active, created_at)
documents (id, shop_id, customer_id, created_by, template_id, reference_no, fields_data, status, pdf_path, docx_path, generated_at, voided_at)
document_history (id, document_id, user_id, action, metadata, created_at)
```

### Month 6: Shop-to-Shop & Remote Operators

#### Task 6.1: Shop-to-Shop Job Sharing
- Shop A receives an order it cannot fulfill (too busy, out of scope)
- Shop A posts it as a "shared job" visible to other shops
- Shop B accepts the job, fulfills it, delivers to Shop A
- Shop A marks it complete for the customer
- Commission split: platform takes %, Shop A gets %, Shop B gets %
- Trust system: each shop has a "completion rate" score

#### Task 6.2: Remote Operators
- Operators register on the platform with skills & experience
- Shops can hire remote operators for specific tasks
- Operators work remotely, generate documents under the shop's name
- Shop reviews operator's work before delivering to customer
- Payment: operator paid per document or hourly (via wallet, Phase 3)
- Operator dashboard: see assigned work, submit documents, track earnings

## ARCHITECTURE DECISIONS

### Custom PHP MVC
- No heavy framework — lightweight custom MVC keeps full control and zero bloat
- Structure: `controllers/` handle requests, `models/` handle data, `views/` render HTML
- Router: single `index.php` entry point with URL rewriting (Apache .htaccess / Nginx config)
- Autoload: Composer PSR-4 autoloading for classes
- Middleware pattern: auth check, permission check, CSRF protection applied per route

### Monolith-First, Modular Later
- Modules separated by folder structure, not services
- Extract to microservices only when specific modules need independent scaling
- Proven approach: Basecamp, GitHub, Shopify all started monolithic

### Frontend: Server-Rendered HTML + Vanilla JS
- Pages rendered server-side via PHP templates (header, content, footer pattern)
- JavaScript kept minimal and modular — add interactivity only where needed
- Use Alpine.js for reactive components (dropdowns, modals, toggles) without React
- Tailwind CSS for styling — compile once, no JS build step
- AJAX for dynamic updates (search, inline saves, chat) via vanilla fetch()

### PDF Generation Strategy
- **Dompdf** or **mPDF** — PHP-native PDF generation
- Embed Bangla fonts (Noto Sans Bengali, Nikosh, or SolaimanLipi) directly in PDF
- Templates: PHP renders HTML with {variables} substituted, then Dompdf converts to PDF
- Async generation via MySQL jobs table: background cron picks up pending jobs
- Fallback: direct sync generation for simple documents (instant download)

### File Storage
- Local filesystem for development + Phase 1
- Organized as: `/storage/shops/{shop_id}/documents/{year}/{month}/{filename}.pdf`
- File metadata stored in MySQL (path, size, type, created_at)
- Cloud backup via cron (rsync or rclone to cloud storage) in Phase 3
- Document access: PHP script serves file (not direct URL) for access control

## API DESIGN PRINCIPLES

### RESTful API (PHP)
- Versioned: `/api/v1/...`
- Authenticated via Bearer tokens (random 64-char tokens stored in MySQL)
- Rate limited: 60 requests/min per user (1000 for paid plans)
- Pagination: page-based (page & per_page params)
- JSON responses with consistent structure
- Response format:
```json
{
  "data": { ... },
  "meta": { "current_page": 1, "per_page": 25, "total": 100 },
  "links": { "first": "...", "last": "...", "prev": null, "next": "..." }
}
```
- Error format:
```json
{
  "message": "Validation failed.",
  "errors": { "name": ["Name is required"] }
}
```

### Key Endpoints
```
GET    /api/v1/customers          List customers
POST   /api/v1/customers          Create customer
GET    /api/v1/customers/{id}     Get customer
PUT    /api/v1/customers/{id}     Update customer
DELETE /api/v1/customers/{id}     Delete customer
GET    /api/v1/customers/{id}/timeline   Customer timeline
GET    /api/v1/customers/{id}/documents  Customer documents

GET    /api/v1/documents          List documents
POST   /api/v1/documents          Generate document
GET    /api/v1/documents/{id}     Get document details
GET    /api/v1/documents/{id}/download   Download PDF
POST   /api/v1/documents/{id}/void       Void document
POST   /api/v1/documents/{id}/regenerate Regenerate

GET    /api/v1/services           List services
POST   /api/v1/services           Create service
GET    /api/v1/services/{id}      Get service details
POST   /api/v1/orders             Place order
GET    /api/v1/orders             List orders
GET    /api/v1/orders/{id}        Order details

GET    /api/v1/wallet             Get wallet balance
POST   /api/v1/wallet/deposit     Deposit funds
POST   /api/v1/wallet/withdraw    Request withdrawal
GET    /api/v1/wallet/transactions List transactions
```

## SECURITY ARCHITECTURE

### Authentication
- Password hashing: bcrypt
- OTP: time-limited (5 min), rate-limited (3 attempts)
- Session: HTTP-only cookies + XSRF protection for web, tokens for API
- Failed login: lockout after 5 attempts (15 min)

### Authorization
- Role-based: each action checks permission
- Scope-based: operators see only their shop's data
- Tenant isolation: queries always scoped to `shop_id`

### Data Protection
- All data encrypted at rest (database encryption + encrypted file storage)
- TLS everywhere (HTTPS)
- Environment variables for secrets (never in code)
- Database backups encrypted before transfer
- Personal data (NID, address) encrypted in database columns

### File Security
- Generated documents: signed URLs with expiration (1 hour default)
- Prevent direct file access (serve through app)
- Watermark for previews (optional)
- Virus scanning for uploaded files

### Compliance
- Bangladesh Data Protection Act compliance
- Customer consent for data storage
- Data deletion on shop account closure
- Audit logging for all sensitive operations

## DEPLOYMENT & INFRASTRUCTURE

### Phase 1-2: VPS (DigitalOcean or local BD host, $15-30/mo)
- 2 vCPU, 4GB RAM, 80GB SSD
- LAMP stack: Apache/Nginx + PHP 8.3 + MySQL 8
- No Docker — direct server setup (easier for BD hosting environment)
- Backups: daily mysqldump to remote storage (Google Drive, Dropbox, or Spaces)
- phpMyAdmin or Adminer for database management

### Phase 3-4: Upgraded VPS / Dedicated
- 4-8 vCPU, 8-16GB RAM
- Separate database server (MySQL on its own VPS)
- 2 app servers with load balancer (HAProxy or Nginx)
- CDN for static assets (Cloudflare)
- Read replica for MySQL (reports query from replica)

### Phase 5: Cloud-Native
- Managed MySQL (DigitalOcean Managed DB or AWS RDS)
- PHP app behind load balancer (horizontal scaling)
- Redis for caching and queues (add when needed)
- Multi-region: Singapore for SEA, Mumbai for India

### Monitoring
- **Custom error log dashboard**: parse PHP error logs, show in admin panel
- **MySQL slow query log**: identify performance issues
- **Server monitoring**: htop, glances, or Netdata
- **Uptime Kuma**: uptime monitoring
- **Custom dashboard**: Business KPIs (active shops, documents generated, revenue)

## RISK & MITIGATION

| Risk | Impact | Probability | Mitigation |
|------|--------|------------|------------|
| Slow PDF generation under load | High | Medium | Queue system + Browsershot pool + fallback to DomPDF |
| Government document format changes | High | Medium | Template system (update template, not code); community updates |
| Payment gateway downtime | High | Medium | Multiple gateways (bKash + Nagad + SSLCommerz); queue + retry |
| Low shop adoption | High | Medium | Free tier, onboarding support, offline sales team, referral program |
| Bangla font/rendering issues | Medium | Low | Extensive testing with popular Bangla fonts; browser-based PDF generation |
| Competition (existing shops) | Medium | High | Focus on underserved digital services; build community moat |
| Security breach (customer data) | Critical | Low | Encrypted storage, audit logs, regular security audits, limited data retention |
| Platform fraud (fake orders, fake reviews) | Medium | Medium | Escrow system, phone verification, reputation scores, manual review flags |
